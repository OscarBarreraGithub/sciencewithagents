# Scope and checks

This checklist records what the starter contains. A checked item means the instructions or artifact are present, not that every integration has been exercised on every host. The package was reviewed against the accumulated design inventory and the later requests to simplify the layout and preserve private activity records.

## Earlier ideas retained without expanding the default

The older application and group work informed the instructions for unresolved requests, imports, pauses, attribution, and shared messages. Import actual scientific files as well as a chat summary, audit remaining requests, preserve missing/external material, and avoid overwriting earlier contributions. Keep personal conversations private. Group summaries can link to permitted scientific evidence; a private catch-up request is not automatically a group post.

Resource monitoring, multiple accounts/computers, large-data sharing choices, cluster-tool integrations such as QUARK, arXiv/source readers, source-to-PDF navigation, Overleaf, and visual views of people/dependencies remain optional extensions. Large results can be shared as contents, as a versioned reference, or kept private with limitations stated. Existing tools can provide these facilities; they are not installation requirements.

A separate website with group-chat summaries and LaTeX writing remains later work. Its access rules, hosting, compilation, and costs need a concrete design when requested. Institutional adoption, teaching, and governance can build on the public method; they do not require every individual installation to run a group service. No new custom UI, dots integration, or formal-verification provider is bundled.

The starter uses conservative defaults for previously open choices: hold only the affected action on conflicting instructions; preserve local edits when updating; keep native monitoring optional; bound unresolved review rounds; publish this kit separately from the earlier app. Users can change project policies explicitly. Role-specific model/account preferences belong in the private workspace note and remain unchanged for existing projects unless requested.

## Validation and remaining limits

The release checks cover local documentation links, tracked-file privacy exclusions, a clean checkout, project Git boundaries, and the paper build/render. The prior synthetic artifact tests checked packaging mechanics; they are not a privacy certificate or real-project reproduction study.

The November 17 starter check passed: 21 distributed files; 76 local links in a fresh clone; 19 external documentation links; private workspace/import/record exclusions; an independently initialized project repository; and an explicitly selected scientific ZIP excluding a synthetic private transcript. The manuscript built twice with no unresolved references or overfull boxes, remained five pages, and all pages were visually inspected. The content audit mapped 187 earlier inventory items, including 120 previously selected items, to their current instructions, paper treatment, or explicit optional/later scope. These counts describe this release's audit.

Still host-specific: instruction loading after actual compaction, native completion hooks, durable capture of live manager/worker activity, browser read/write handoffs, scheduler delivery, and hard usage controls. Setup must verify the route it establishes and report untested capabilities. A successful local cross-provider manuscript review does not establish all accounts or platforms.

At each future change, ask: can the existing notebook, Git history, or native tool do this already? Add a file or helper only for a concrete unmet need. Keep this checklist aligned with the documented behavior and evidence.
