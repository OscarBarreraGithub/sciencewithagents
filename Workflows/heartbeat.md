# A periodic check

Use only when the researcher requests monitoring. A lightweight model can check compact project reports and wake the existing orchestrator when attention is needed. Fifteen minutes is a useful starting cadence; use Luna if available and selected, or another agreed inexpensive model. Do not silently substitute a provider or model.

Inspect the host's native scheduler, execution location, project access, usage sources, and route to the existing orchestrator. Read current documentation, establish the requested schedule, and verify one actual check and acknowledgment. A prompt or cloned folder does not create a scheduled process. Report what happens when the host sleeps, access expires, or delivery fails.

Read the notebook's Now section, pending reviews/questions, actual manager/job state where accessible, Git changes, and available usage. Look for stale reports, unexpected activity, failed checks, unreviewed consequential changes, missing checkpoints, and budget concerns. Diff size is a signal to investigate, not proof that work is chaotic. Avoid rereading whole histories on every tick.

When nothing needs attention, stay quiet. On a new concern, send a concise evidence-linked notice to the existing orchestrator; do not spawn another orchestrator at every tick. Retain unresolved delivery and avoid duplicate alerts. Monitoring does not authorize changing project work or bypassing a stop.

Each flagged concern needs an owner, evidence, and a next action. Keep deterministic observations, such as an unavailable remote or failed process, distinct from model judgments about scientific progress. Use actual limits and supporting evidence before interpreting a measurement as a reason to stop work. Explain uncertainty and repair mistaken holds only within existing authority.

For a percentage-of-weekly-budget request, establish which account, allowance, reset interval, observed consumption, and stop controls exist. Label estimates, unavailable counters, and the observer's own cost. Use host limits for hard enforcement. A notebook policy alone cannot enforce spending.

Context is the finite information available to a model for its next work. Reusing stable context may reduce costs through caching, but cache eligibility, retention, timing, and prices vary. There is no universal cadence that is cheapest. Measure the chosen route and experiment within an agreed budget. This cost detail belongs in the docs, not the short paper.

Save the schedule's native reference, selected model, last observed result, escalation route, and how to disable it in the private workspace note. Check failures of the monitor itself; never claim continuous coverage from the existence of a schedule.
