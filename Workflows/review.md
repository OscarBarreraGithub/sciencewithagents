# Review a scientific result

Read the project's assignment and selected instruction revision. Identify the exact derivation, code, figure, or claim to check, its assumptions, dependencies, and expected criteria. Preserve the producer's identity and distinguish review from authorship.

Choose a suitable independent person or agent when available. Use native delegation or the [cross-agent method](cross-agent.md); if no independent reviewer is available, label a self-check as such. Give the reviewer a bounded brief and the relevant files, with its own identity and scope. Do not forward personal chats.

Request concrete findings with evidence: an error location, failed limit/tolerance, unsupported citation, missing premise, or proposed targeted correction. A prose review can return original/replacement sentences and reasons for the editor to accept or reject. The reviewer must not certify unavailable evidence.

The manager inspects the findings, records accept/adapt/reject decisions with scientific reasons, and saves corrections with appropriate checks. After two unresolved rounds, report the disagreement instead of running an indefinite loop. Preserve failed and contradictory reviews. Recheck changed claims against the relevant criteria; an old pass does not automatically apply.

Numerical checks, human review, and formal proof can be attached to the same result version. Keep each method's assumptions, scope, tool/version, outcome, evidence, and repeatability. Distinguish imported provider assertions from independently repeated checks. No provider-specific proof format is required for the core project.
