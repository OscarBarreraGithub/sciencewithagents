# Cross-agent communication

Use when requested, including “Use the sciencewithagents.com cross-agent instructions.” Follow the [update procedure](README.md#updates) and record the revision used. Basic setup leaves this method inactive.

The outcome is a bounded assignment delivered to the intended agent, an attributable response for the same project/task, and inspection by the manager. A copied instruction file or installed CLI does not establish that exchange.

## Find and establish a route

Read the project instructions, current assignment, and existing non-secret setup. Inspect native delegation/messaging first. If it cannot reach the requested provider, investigate that provider's supported local or hosted execution tools. A browser without execution access may guide setup or use an explicit handoff; record where execution actually occurs.

Consult current official installation, authentication, programmatic-use, model, and permission documentation. Inspect the installed tool's version/help and intended profile. Determine what must run on which machine, how this user signs in, which models/effort settings are actually available, what instructions/tools the execution mode loads, and how completion or continuation is reported.

For Claude Code, start with [quickstart](https://code.claude.com/docs/en/quickstart), [setup](https://code.claude.com/docs/en/setup), [authentication](https://code.claude.com/docs/en/authentication), [programmatic use](https://code.claude.com/docs/en/headless), [CLI reference](https://code.claude.com/docs/en/cli-reference), and [model configuration](https://code.claude.com/docs/en/model-config). For Codex, use its [CLI](https://learn.chatgpt.com/docs/codex/cli), [noninteractive mode](https://learn.chatgpt.com/docs/non-interactive-mode), and current configuration documentation. Follow moved links through the official index.

Establish missing prerequisites through the user's own account and supported installation route. Guide native sign-in when needed; the user completes secrets and consent in the provider's interface. Never copy the maintainer's credentials, change billing routes silently, or assume desktop sign-in automatically authenticates a separate execution mode. A minimal execution flag may change authentication or instruction loading; verify its current behavior before using it.

## Send the assignment and inspect the result

Give the collaborator its own participant tag, role, project/task reference, exact source version, permitted actions, expected output, and stopping condition. Send only the needed scientific material. Personal conversations and unrelated projects stay private. Record the intended assignment before launch and the returned native reference afterward.

Use structured input or a file for scientific text; do not interpolate it into a shell command. Select only required tools through native permissions when possible. A review can ask for targeted suggestions while preserving the source. Requested provider/model/effort and reported runtime metadata are separate fields; missing identity remains unknown.

Inspect the native status and returned content against the task. Check that it refers to the intended version and includes the required evidence. The responsible editor/manager records accepted, adapted, or rejected suggestions and the reason. An actual requested task is enough for connection verification; no separate showcase project is required.

A timeout may leave work running. Inspect the saved native task before retrying or resuming, and stop only work belonging to this assignment within the user's instructions. Authentication, unsupported flags, unavailable models, and malformed output need different repairs. Do not silently substitute another model or duplicate the worker.

If ongoing exchange is needed, establish the native continuation mechanism for that exact task and verify a follow-up response. A native session identifier is not automatically portable across computers or browser interfaces. If continuation is unavailable, use saved scientific state and an explicit new assignment.

## Save how to repeat it

Record the selected route, current sources/versions, non-secret configuration, actual supported invocation, native task reference, evidence of completion, and useful failure findings in the private setup note and scientific notebook as appropriate. Preserve available raw records privately under the [records protocol](../docs/records.md).

On return, reuse verified setup and inspect what changed. Preserve active assignments and local adaptations through updates. A prior successful local review establishes only that route and account at that time; it does not prove every platform, browser bridge, or requested model works.
